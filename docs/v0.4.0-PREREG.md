# v0.4.0 release run: pre-registration (2026-10-19)

Written and committed before the run. v0.4.0 is v0.3.0 plus S32, the cache warmer, nothing else:
- **`bramley warm`.** A headless command that fills the S29 disk cache while the app is closed:
  - it exits at once if the app is running, and stops if the app starts;
  - at most 60 Apple requests a run, 1 API request per second;
  - list pages are refreshed after 30 minutes and track lists after 6 hours, so a fully fresh cache costs 0 requests;
  - a 401 or 403 pauses warming until the app has run again, and a 429 or 5xx backs off from 5 minutes up to 1 hour;
  - a keyring that is locked or doesn't answer means no work and no prompt;
  - listening history is never fetched.
- **A systemd user timer** (`bramley-warm.timer`, every 5 minutes) ships in the release tarball. It is not enabled.

See `docs/s32-warm-PREREG.md` and `docs/s32-warm-RESULTS.md`: a never-visited album took 0.20 s to all visible covers after warming, against 2.01 s cold.

Versions: `crates/app` 0.4.0, a minor bump for a feature. `crates/engine` is unchanged at 0.2.1, so there is no engine publish. The PKGBUILD and README changes for the timer are applied in the AUR bump commit after release, when the tarball carries `packaging/systemd/`.

The integration branch is `natevick/v0.4.0`.
