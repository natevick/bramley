# v0.3.0 release run: pre-registration (2026-10-19)

Written and committed before the run. v0.3.0 is v0.2.1 plus S29, the on-disk cache, nothing else:
- Album art and browse responses (library lists; album, playlist and artist track lists) are cached under `$XDG_CACHE_HOME/bramley`.
- Cached pages show at once and refresh in the background.
- Sign-out wipes the API cache.
- Listening history is never cached on disk.
- See `docs/decisions.md` (2026-10-18), `docs/s29-cache-PREREG.md` and `docs/s29-cache-RESULTS.md`. Warm-cache covers took 7–10% of the cold time on the Songs and Album routes.

Versions: `crates/app` 0.3.0, a minor bump for a feature. `crates/engine` is unchanged at 0.2.1, so there is no engine publish.

The integration branch is `natevick/v0.3.0`.

## The run
`scripts/acceptance.sh v030-counted-1`, counted mode, from a clean tree, at the commit that last changed this file (`git log -1 --format=%H -- docs/v0.3.0-PREREG.md`).

`drive.py` now wipes the isolated cache at every App launch, so every acceptance session starts cold. The gate therefore judges the cold path, which is unchanged in speed against main (S29 RESULTS, cold/main 0.91–0.93). It does not judge the warm path; S29 measured that separately.

## Pass
- The gate PASSes under `docs/acceptance.md` and `docs/s13-acceptance-PREREG.md` Amendments 4–16.
- `realStateUnchanged` is true, and the leak grep is clean.
- `~/.cache/bramley` is not created by the run, because every session uses an isolated `XDG_CACHE_HOME`. Check by hand that it does not exist after the run.

## Decision
- **PASS:** the branch merges to main, then v0.3.0 is released, the AUR package is bumped, and the laptop is updated. Nate approved the two-release plan on 2026-10-19.
- **FAIL:** nothing merges. Name the failing check, and the decision goes to Nate.
- **VOID:** under the existing rules, re-run with the next name (`v030-counted-2`); don't judge it.
