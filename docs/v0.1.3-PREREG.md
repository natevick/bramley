## Covers
Home now draws up to 50 albums from the user's library, so the covers come from the library and not the chart. The F and R checks that count covers are unchanged, as long as 50 covers load. That needs the account's library to have at least 50 albums with usable artwork.
- `gate.py` and `drive.py` count `texturesUploaded`, which is the number of Home textures, against `COVERS = 50`. They do not care where the covers come from.
  - R3 and the R1/R2 windows fail on any sample below 50, and R1's ballast pre-window needs 50.
  - Every main session start waits up to 60 s for 50, `coversFailed` or a banner; the R4/R5 session start waits for 50.
  - F10 waits up to 90 s for 50 after the network returns, and FAILs if it never gets there.
- Home takes `COUNT = 50` albums. It reads library pages until it has 100 candidates or 10 pages, so a library under 50 albums gives under 50 covers. Albums without artwork add to `coversFailed`; a small library does not, so `drive.py` waits out the 60 s.
- A covers shortfall is read against the library size before it is read as a Home regression.

**Measured.** On 2026-10-15 at ff68bba (`natevick/home-library`), in an isolated session with the same `music-user-token` the run copies, Home reached 50 textures in 4.41 s, with 59 covers requested and 0 failed.
