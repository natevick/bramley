## Check by hand
- **No cache left behind.** `~/.cache/bramley` does not exist after the run.
- **No host theme.** The acceptance sessions must not read the host's Omarchy theme. The isolation is `XDG_STATE_HOME` set to `<session config dir>/state`, so the app looks for `<config>/state/omarchy/current/theme/colors.toml`, which does not exist. The run's status files carry no theme field, and the app logs nothing when a theme loads, so the check reads these:
  - **Launch guard.** Every session's `<name>.log` and `<name>.status.json` sit in `target/acceptance/v070-counted-1/`, and each was launched through `assert_isolated`. The verdict's `phaseErrors` is empty and no log or phase error contains `host Omarchy theme could leak`.
  - **Logs.** `grep -il omarchy target/acceptance/v070-counted-1/*.log` finds nothing.
  - **Screenshots.** Before the run, `ls ~/.local/state/omarchy/current/theme/colors.toml`. If it exists, `target/screens/PRIVATE-real-art/acceptance/v070-counted-1/*.png` must not use its `background` colour for the window. If it is absent, say so in the result: the launch guard is then the only evidence.
